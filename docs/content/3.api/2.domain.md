Toutes les routes demandent un utilisateur connecté (jeton JWT) ou une application externe (`Authorization: Bearer rcl_…`, avec ou sans `X-Impersonate-User`). Envoyer `Accept: application/json`. Une application sans impersonation (un PMS pour lui-même) accède aux lieux, ménages, checklists et stock, pas aux comptes, aux personnes ni aux réglages.

## Lieux

`{placeId}` est un UUID : celui de Rocket Place quand il est configuré, sinon celui d'un lieu local. Les routes gardent les chemins de Rocket Place (`/api/places/{placeId}/…`) : pour un PMS, passer de Place à Clean pour le ménage ne change que l'adresse et le jeton.

| Méthode | Route | Rôle |
|---|---|---|
| GET | `/api/places` | Lieux `[{"id", "name", "source": "local" \| "place"}]` |
| GET | `/api/places/{placeId}` | Un lieu (lu dans Place et mis en cache si configuré) |
| POST · PATCH · DELETE | `/api/places` · `/api/places/{placeId}` | Lieux locaux `{"name"}` (administrateur ou application ; 409 si Rocket Place est configuré) |
| GET | `/api/places/{placeId}/stock` | Stock du lieu `[{"id", "name", "level"}]` (celui de Rocket Stock, sinon de Place ; vide sinon) |
| GET · PUT | `/api/places/{placeId}/occupancy` | Séjours du lieu ; PUT `[{"from", "until", "externalRef"?}]` (ou `{"periods": […]}`) remplace la liste (Rocket Host, PMS : applications autorisées) et recalcule `conflict` |
| GET · PUT | `/api/places/{placeId}/cleaning-costs` | Coût par défaut par type, en centimes `{"rental", "personal", "maintenance"}` (`null` = aucun) |

## Ménage

Chaque ménage a un **type** `rental` (entre deux séjours), `personal` (usage du propriétaire) ou `maintenance` : par défaut `rental` si `externalRef` commence par `booking:`, sinon `personal`. Son **origine** `origin` vaut `clean` (créé dans Rocket Clean), `recurrence`, ou pour une application `host`, `pms` (défaut) ou `place` (champ `origin` du POST), avec `originApp` = nom de l'application. Une application modifie et supprime ses propres ménages et ceux créés par des personnes, jamais ceux d'une autre application (403). `cost` : coût en centimes (facultatif, défaut : coût du lieu pour le type). `conflict` : ménage personnel ou d'entretien qui chevauche un séjour (`/occupancy`).

Utilisable par une application pour elle-même (`Authorization: Bearer rcl_…` sans `X-Impersonate-User`), par exemple un PMS qui crée un ménage après chaque départ.

| Méthode | Route | Rôle |
|---|---|---|
| GET | `/api/cleanings` | Ménages d'un jour et ménages en retard (`?date=AAAA-MM-JJ`, défaut aujourd'hui, `all` sans filtre ; `?mine=1` ; `?place=<placeId>` ; `?type=`) |
| GET | `/api/places/{placeId}/cleanings` | Ménages d'un lieu (`?type=`) |
| GET | `/api/cleanings/export` | Export des coûts `{"total", "count", "items": [...]}` en centimes (`?type=rental`, `?place=`, `?from=`/`?to=` AAAA-MM-JJ inclus ; ménages annulés exclus). Administrateur ou application |
| POST | `/api/places/{placeId}/cleanings` | Planifie `{"scheduledAt", "dueAt"?, "label"?, "assigneeEmail"? \| "assigneeId"?, "notes"?, "externalRef"?, "type"?, "cost"?, "origin"?}` (administrateur ou application). Idempotent par `externalRef` (unique par lieu) : 201 à la création, 200 avec le ménage existant ensuite. Avec une personne : e-mail d'attribution |
| GET · PATCH · DELETE | `/api/cleanings/{id}` | Un ménage. PATCH : `status` (`todo`, `in_progress`, `done`, `cancelled`), `notes`, `checklist: [{"index", "done"}]` pour la personne attribuée ; `label`, `scheduledAt`, `dueAt`, `assigneeEmail`/`assigneeId` (null = personne), `type`, `cost` et DELETE : administrateur ou application |
| POST | `/api/cleanings/{id}/photos` | Multipart `file` + `moment` (`before`, `after`, `damage`), vers Rocket Cloud |
| GET | `/api/cleanings/{id}/photos/{fileId}` | Contenu d'une photo du ménage |
| POST | `/api/cleanings/{id}/stock` | `{"stockLevelId", "level": "ok" \| "low" \| "empty", "quantity"?}` : avec Rocket Stock, enregistre une consommation (`consume`, `externalRef` `cleaning:<id>:<levelId>`, `usage` selon le type) seulement si `quantity` est donnée ou si l’état passe à `low`/`empty` (1 dans ce cas), puis l’état ; sinon change le niveau dans Rocket Place ; le note sur le ménage (404 sans stock) |
| GET · POST · DELETE | `/api/cleanings/{id}/link` | Lien secret sans compte `{"url", "path", "expiresAt"}` : GET le crée au besoin, POST le régénère (l'ancien ne marche plus), DELETE le révoque |
| GET · PUT | `/api/places/{placeId}/cleaning-checklist` | Modèle de checklist du lieu par type (`?type=`, défaut `rental` ; un type sans modèle reprend celui de `rental`) ; PUT `{"items": ["Draps changés", …]}` (administrateur ou application) |
| GET | `/api/cleaning-assignees` | Comptes actifs à qui attribuer un ménage (administrateur) |
| GET · PUT | `/api/cleaning-settings` | E-mails `{"assignment", "late", "summary"}` (booléens, administrateur) |

### Récurrences

| Méthode | Route | Rôle |
|---|---|---|
| GET · POST | `/api/places/{placeId}/recurrences` | Récurrences du lieu ; POST `{"type"?, "label"?, "frequency": "weekly" \| "monthly", "weekdays"?: [1..7], "monthDay"?: 1..31, "nth"?: 1..5 \| -1, "nthWeekday"?: 1..7, "time"?: "HH:MM", "durationMinutes"?, "assigneeId"? \| "assigneeEmail"?, "checklist"?: [...], "cost"?, "active"?, "startsOn"?, "endsOn"?}` |
| GET · PATCH · DELETE | `/api/recurrences/{id}` | Une récurrence ; PATCH et DELETE retirent ses ménages futurs encore « à faire », régénérés ensuite |

Les ménages sont générés chaque jour (worker, 3 h) pour les `CLEANING_RECURRENCE_DAYS` jours à venir (14 par défaut), et aussitôt à l'enregistrement : `origin` `recurrence`, `externalRef` `recurrence:<id>:<AAAA-MM-JJ>` (idempotent).

### Lien secret (public, sans compte)

Limité à un seul ménage, 120 requêtes par minute et par IP (10 jetons invalides par minute, puis 429), réponses `Cache-Control: no-store` et `X-Robots-Tag: noindex`. Valable jusqu'au lendemain de l'échéance (ou du jour prévu).

| Méthode | Route | Rôle |
|---|---|---|
| GET · PATCH | `/api/public/cleaning/{token}` | Le ménage (avec `stock` et `expiresAt`) ; PATCH `status`, `notes`, `checklist` (le reste est ignoré) |
| POST | `/api/public/cleaning/{token}/photos` | Multipart `file` + `moment` |
| GET | `/api/public/cleaning/{token}/photos/{fileId}` | Contenu d'une photo de ce ménage |
| POST | `/api/public/cleaning/{token}/stock` | Niveau d'un article du lieu |

Exemple (PMS, après un départ) :

```bash
curl -X POST https://clean.example.org/api/places/<uuid>/cleanings \
  -H 'Authorization: Bearer rcl_…' -H 'Accept: application/json' -H 'Content-Type: application/json' \
  -d '{"scheduledAt":"2026-10-05T11:00:00+02:00","dueAt":"2026-10-05T16:00:00+02:00","label":"Ménage après Sofia Rossi","externalRef":"booking-42"}'
```

## Linge (`/api/linen/*`)

Module isolé (voir la page Linge). Lecture : tout compte ou application agissant pour elle-même ; modifications de configuration : administrateur ou application.

| Méthode | Chemin | Rôle |
|---|---|---|
| GET · POST | `/api/linen/types` | types de linge `{name, weightGrams?, stockItemId?, position?}` ; `PATCH · DELETE /api/linen/types/{id}` (409 si déjà utilisé) |
| GET · POST | `/api/linen/kits` | kits `{name, lines: [{typeId, qty}]}` ; `PATCH · DELETE /api/linen/kits/{id}` |
| GET · PUT | `/api/linen/places/{placeId}/needs` | besoins `[{kitId, units, kitsPerUnit}]` (remplace la liste) |
| GET | `/api/linen/summary?place=` | quantités par état, emplacement (`reserve`, `logement`), type, kits propres |
| GET · POST | `/api/linen/places/{placeId}/movements` | mouvements ; POST `{type, from?, to?, qty, reason?, externalRef?, origin?, usage?, fromLocation?, toLocation?}` strict (422 si pas assez), 200 `alreadyRecorded` si la référence existe |
| PUT | `/api/linen/places/{placeId}/counts` | inventaire `[{type, state, location?, qty}]` |
| GET · POST | `/api/cleanings/{id}/linen` | étape Linge d'un ménage `{key?, removed, placed, damaged: [{kit|type, qty}]}`, références `cleaning:<id>:linen:<key>:<action>:<typeId>` ; aussi `/api/public/cleaning/{token}/linen` |
| GET · POST | `/api/linen/washes` | lessives `{placeId, scheduledAt, lines, label?, usage?, assigneeEmail?|assigneeId?}` ; `PATCH /api/linen/washes/{id}` `{steps, status}` (done : sale → propre, `wash:<id>:<typeId>`) ; `DELETE` |
| GET · POST | `/api/linen/laundries` | blanchisseries `{name, orderEmail, pricing: kg|piece, pricePerKg, piecePrices, turnaroundDays}` ; `PATCH /api/linen/laundries/{id}` |
| GET · POST | `/api/linen/batches` | lots `{laundryId, placeId, lines, weightKg?, usage?, note?}` : sale → en blanchisserie |
| POST | `/api/linen/batches/{id}/return` | retour compté `{returned, damaged?, weightKg?}` : propres, abîmés, manquants (perdus), écarts, coût |
| GET · POST | `/api/linen/batches/{id}/email` | aperçu de l'e-mail de dépôt ; envoi `{confirm: true}` (administrateur, une fois) |
| GET | `/api/linen/readiness?place=&date=&days=` | prêt / juste / manque par arrivée |
| GET | `/api/linen/alerts` | kits, lots en retard, pertes du mois |
| GET | `/api/linen/costs?from=&to=&place=&format=csv` | coûts par usage (lots revenus) |
| GET · POST | `/api/linen/replacements` | linge perdu/abîmé ; POST `{placeId, type, qty, key?}` : sortie dans Rocket Stock (`POST /api/movements` type `out`, `linen:replace:<key>`) puis retrait du compte ; 409 sans Rocket Stock |
