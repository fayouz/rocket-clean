## Comptes locaux

Un administrateur les crée depuis la page **Utilisateurs** (mot de passe de 12 caractères minimum), ou en ligne de commande :

```bash [Terminal]
php bin/console app:user:create jean@exemple.com 'un-mot-de-passe-long' [--admin]
```

## Annuaire LDAP

### Configuration

La configuration se fait dans **Administration → Serveurs d’authentification → LDAP** :

| Champ | Exemple |
|---|---|
| **URL du serveur** | `ldaps://ldap.exemple.com:636`, ou `ldap://…:389` avec **STARTTLS** |
| **Base de recherche** | `ou=people,dc=exemple,dc=com` |
| **Compte de service** (DN, mot de passe) | Compte en lecture, utilisé pour les synchronisations |
| **Filtre** | `(objectClass=inetOrgPerson)` ; Active Directory : `(&(objectClass=user)(memberOf=…))` |
| **Groupe des administrateurs** | `cn=rocket-admins,ou=groups,dc=exemple,dc=com` (optionnel) |
| **Attributs** | email `mail` (Active Directory : `mail` ou `userPrincipalName`), prénom `givenName`, nom `sn`, groupes `memberOf` |

- **Tester** : essaie les valeurs saisies **sans les enregistrer**. Rocket Clean se connecte avec le compte de service, puis cherche les utilisateurs et en montre un aperçu (nom, email, DN, administrateur ou non).
- **Enregistrer** : la configuration est conservée en base, avec le mot de passe du compte de service **chiffré** (clé `SECRETS_ENCRYPTION_KEY`, ou `APP_SECRET` si elle est vide). Elle s'applique immédiatement, sans redémarrage. Laissez le mot de passe vide pour garder celui qui est enregistré.

### Valeurs par défaut (.env)

Les variables `LDAP_*` restent la **configuration par défaut** : elles s'appliquent tant que rien n'est enregistré dans l'administration. Le bouton **Revenir aux valeurs par défaut (.env)** supprime la configuration enregistrée pour les appliquer de nouveau.

| Variable | Rôle | Défaut |
|---|---|---|
| `LDAP_ENABLED` | `1` pour activer | `0` |
| `LDAP_URL` | URL du serveur | `ldap://localhost:389` |
| `LDAP_START_TLS` | `1` pour STARTTLS sur `ldap://` | `0` |
| `LDAP_BASE_DN` | Base de recherche | — |
| `LDAP_SEARCH_DN` / `LDAP_SEARCH_PASSWORD` | Compte de service | — |
| `LDAP_USER_FILTER` | Filtre des utilisateurs | `(objectClass=inetOrgPerson)` |
| `LDAP_ADMIN_GROUP_DN` | Groupe des administrateurs | — |
| `LDAP_ATTRIBUTE_EMAIL`, `LDAP_ATTRIBUTE_FIRST_NAME`, `LDAP_ATTRIBUTE_LAST_NAME`, `LDAP_ATTRIBUTE_GROUPS` | Attributs lus | `mail`, `givenName`, `sn`, `memberOf` |

C'est pratique pour préconfigurer une installation (Docker, Ansible…) tout en laissant les administrateurs l'ajuster ensuite.

API (administrateurs) : `GET`, `PUT` et `DELETE /api/ldap/config`, `POST /api/ldap/test`.

### Synchronisation

```bash [Terminal]
php bin/console app:ldap:sync            # à planifier (cron)
php bin/console app:ldap:sync --dry-run  # simulation, rien n'est écrit
```

Ou depuis la page **Utilisateurs** ou **Annuaire LDAP**, avec les boutons **Simuler la synchro** et **Synchroniser**.

- Les entrées de l'annuaire sont **créées ou mises à jour** (email, prénom, nom).
- Les comptes LDAP qui ont disparu de l'annuaire sont **désactivés**, pas supprimés : leurs impressions restent dans l'historique.
- Un compte **local** avec le même email n'est **jamais** repris par l'annuaire. Il est signalé comme conflit.
- Si un groupe des administrateurs est défini, le rôle administrateur suit l'appartenance au groupe (attribut des groupes). Sinon, il se gère dans l'application.

### Connexion

Un compte LDAP se connecte avec son mot de passe d'annuaire, vérifié par un *bind* sur son DN. Rocket Clean ne stocke pas ce mot de passe. Un mot de passe vide est toujours refusé : sur la plupart des serveurs, il donnerait un bind anonyme réussi.

::tip
Pour qu'une application agisse au nom de ses utilisateurs, ceux-ci doivent exister dans Rocket Clean. Si les deux partagent le même annuaire, planifiez la synchronisation LDAP, ou utilisez l'authentification unique (Rocket Auth).
::
