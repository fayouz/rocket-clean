Rocket Clean peut déléguer la connexion à un fournisseur **OpenID Connect** : Rocket Auth, Keycloak, Entra ID, Google Workspace… La page de connexion affiche alors un bouton **Se connecter avec …** pour chaque fournisseur actif. Les comptes locaux et LDAP continuent de fonctionner.

## Déclarer Rocket Clean chez le fournisseur

Créez un client **confidentiel** avec le flux *authorization code* :

| Paramètre | Valeur |
|---|---|
| URL de retour (redirect URI) | `https://pms.exemple.fr/auth/callback` (l'adresse de l'interface) |
| Scopes | `openid email profile`, plus `groups` pour gérer les administrateurs depuis le fournisseur |
| PKCE | S256 (toujours envoyé par Rocket Clean) |

Dans Rocket Auth : **Administration → Clients OAuth → Nouveau client**. Notez le *Client ID* et le secret, qui n'est affiché qu'une fois.

## Ajouter le fournisseur dans Rocket Clean

**Administration → Serveurs d'authentification → Ajouter un serveur → OpenID Connect**, puis :

- **Émetteur (issuer)** : l'URL publique du fournisseur. Son document de découverte est lu sur `<émetteur>/.well-known/openid-configuration`.
- **Client ID** et **secret**. Le secret est chiffré en base et n'est jamais renvoyé par l'API.
- **Groupe administrateurs** (optionnel) : un utilisateur dont la revendication `groups` contient cette valeur reçoit le rôle administrateur, et le perd sinon. Laissez vide pour gérer les administrateurs dans Rocket Clean.
- **URL interne** (optionnel) : l'adresse du fournisseur vue depuis l'API quand elle diffère de l'émetteur. Exemple : `http://auth-api` dans un réseau Docker, avec l'émetteur `http://localhost:3100`.
- **Relier les comptes existants de même email** : à réserver à un fournisseur de confiance. Sans cette option, une connexion est refusée si un compte local ou LDAP utilise déjà la même adresse.

Le bouton **Tester la connexion** lit le document de découverte avant l'enregistrement.

## Ce qui se passe à la connexion

1. L'interface redirige vers le fournisseur avec `state`, `nonce` et un défi PKCE (S256), gardés dans l'onglet.
2. Au retour sur `/auth/callback`, elle transmet le code à l'API (`POST /api/auth/oidc/callback`).
3. L'API échange le code avec le secret du client, puis vérifie la signature du jeton d'identité (RS256, clés JWKS), l'émetteur, l'audience, l'expiration et le `nonce`.
4. Le compte est retrouvé par son identifiant chez le fournisseur (`sub`), ou créé à la première connexion (source « SSO »). Prénom, nom et adresse suivent le fournisseur.
5. L'API ouvre une session Rocket Clean, comme une connexion par mot de passe.

Un compte SSO ne peut pas se connecter par mot de passe. Pour le bloquer, désactivez-le dans **Utilisateurs**. Supprimer le serveur peut aussi désactiver tous ses comptes.

## Supervision

Le worker vérifie chaque fournisseur actif toutes les 5 minutes (document de découverte). Le tableau de bord affiche le résultat dans **Authentification unique**.

## API

| Méthode | Chemin | Accès |
|---|---|---|
| `GET` | `/api/auth/providers` | public : fournisseurs actifs (nom, point d'autorisation, client ID, scopes) |
| `POST` | `/api/auth/oidc/callback` | public : `{ provider, code, codeVerifier, redirectUri, nonce }` → `{ token }` |
| `POST` | `/api/authentication_servers/oidc/test` | administrateur : `{ url, internalUrl }` |
| `GET`, `POST`, `PATCH`, `DELETE` | `/api/authentication_servers` | administrateur (`type: "oidc"`, `clientId`, `clientSecret`, `scopes`, `internalUrl`, `adminGroupDn`, `linkExistingAccounts`) |

## Mode suite

Plutôt qu'un fournisseur déclaré à la main, Rocket Clean peut rejoindre la suite Rocket : renseignez `ROCKET_AUTH_URL`, `ROCKET_AUTH_INTERNAL_URL`, `ROCKET_AUTH_CLIENT_ID` (`rocket-clean`), `ROCKET_AUTH_CLIENT_SECRET`, `ROCKET_AUTH_ADMIN_GROUP`, `ROCKET_PUBLIC_URL` et `ROCKET_INTERNAL_URL`. La connexion passe alors uniquement par Rocket Auth, le menu affiche le sélecteur des applications, et la déconnexion est propagée. Rocket Cloud (photos) et Rocket Place (lieux, stock) sont appelés avec un jeton Rocket Auth (client credentials, audiences `rocket-cloud` et `rocket-place`) ; `ROCKET_CLOUD_TOKEN` / `ROCKET_PLACE_TOKEN` servent de repli. Rocket PMS peut appeler Rocket Clean de la même façon si un administrateur lie une application au client `rocket-pms` (Administration → Applications, « Client Rocket Auth »).
